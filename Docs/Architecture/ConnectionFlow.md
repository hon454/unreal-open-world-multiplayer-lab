# 로컬 및 EOS 접속 흐름

상태: 책임 분리 합의. EOS API와 인증 구현 방식은 미정.

## 결정

EOS 연동과 독립적으로 이동·복제를 검증할 수 있도록 로컬 직접 접속을 유지한다.
두 경로는 공통 맵·GameMode·캐릭터를 사용한다.

| 책임 | 범위 |
|---|---|
| 온라인 서비스 | EOS 인증, 서버 세션 등록·검색·참가·종료 |
| 접속 흐름 | 로컬/EOS 선택, 접속 대상 결정, 서버 이동, 실패·재접속 |
| 게임플레이 | 스폰·이동·복제. EOS 로그인·세션 API에 직접 의존하지 않음 |

- 로컬: EOS 없이 IP 직접 접속.
- EOS: 인증 → 세션 검색·참가 → 게임 서버 접속.
- Epic 계정 기반 개발 로그인에는 Dev Auth Tool 사용을 검토한다.
- 접속·온라인 서비스 수명은 GameInstanceSubsystem에서 관리하는 방향으로 시작한다. 범용 플랫폼 프레임워크는 만들지 않는다.

## 인증 경계

인증 생략은 로컬 개발 서버에만 허용한다.
서비스용 서버는 서버 측 인증을 검증하며, 클라이언트 옵션이나 EOS 실패로 인증 없는 경로를 허용하지 않는다.

## 미정

- Online Subsystem EOS / Online Services 중 통합 API 선택.
- EOS 개발 환경과 테스트 계정 준비.
- 개발·서비스 구성 분리 및 서버 인증 강제 방법.
- 로컬/EOS NetDriver 구성과 같은 PC·LAN·외부 접속 주소 처리.

이번 범위는 인증·세션·접속까지다. 친구·초대·음성·안티치트·자동 매치메이킹은 제외한다.
