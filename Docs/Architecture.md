# 설계 초안

상태: 계획. 실제 클래스·함수 이름은 구현 후 연결합니다.

## 테스트 제어

UMG 패널 → 소유 PlayerController의 Server RPC → 서버 테스트 관리자 → 결과·설정 상태 복제.

- 서버가 액터 생성·제거, 실험 진행, 최적화 정책을 관리합니다.
- 테스트 운영자만 전역 실험을 제어합니다. 요청 수량·빈도를 서버에서 검증합니다.
- 요청한 값과 서버가 적용 확인한 값을 구분합니다.
- UI 버튼과 자동 A/B 실행은 같은 실험 제어 로직을 호출합니다.
- 트레이스는 서버·클라이언트별로 기록하고 공통 Run ID로 연결합니다.

## 월드와 복제

- 첫 버전은 작은 월드를 서버가 전체 로드하고 클라이언트 스트리밍을 검증합니다.
- World Partition 로딩과 Iris 공간 필터링은 별도 설정·측정 대상으로 둡니다.
- Iris를 기본 시스템으로 고정합니다. Replication Graph는 범위에 포함하지 않습니다.
- Push Model과 런타임 정책 전환은 선택한 엔진 버전의 API·설정을 확인한 뒤 구현합니다.
- 필터로 복제가 중단되었다가 재진입했을 때 현재 상태를 복원해야 합니다.

## 이동과 애니메이션

- 기본 이동은 CharacterMovementComponent를 사용합니다.
- Sprint 입력은 예측, 서버 재현, 보정 후 재시뮬레이션에 반영합니다.
- 오류 재현 모드와 정상 성능 기준 모드를 명확히 구분합니다.
- 지속 동작은 Action ID, 실행 Sequence ID, 서버 시작 시각, 재생 속도, 취소 상태로 표현하는 방향을 검토합니다.
- Root Motion과 복잡한 전투 시스템은 후순위입니다.
