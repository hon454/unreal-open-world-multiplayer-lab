# Push Model과 우선순위

상태: **계획 / 미구현 / 미측정**. 아래 버튼과 시나리오는 구현 예정입니다.

## 목적

변경 감지 CPU 비용과 제한된 전송 예산의 배분을 각각 독립적으로 검증한다.

## 예정 UI

Push Model 비교와 중요도 정책 비교는 별도 실험으로 실행한다.

## 시나리오

Push 등록과 Dirty 표시가 올바른 상태에서 지원되는 모드로 비교한다. 우선순위는 제한된 예산에서 가까운 중요 액터와 기타 액터를 비교한다.

## 정확성 검증

Dirty 누락 여부, 모든 상태 변경의 도달, 중요도 변경 후 갱신과 범위 복귀를 확인한다. 엔진 버전별 API·런타임 전환 지원을 먼저 확인한다.

## 측정 지표

Push는 폴링·변경 감지 CPU 비용, 우선순위는 액터별 업데이트 간격·상태 지연을 본다. 총송신량 감소를 우선순위의 필수 효과로 가정하지 않는다.

## 재현 절차와 구현 근거

엔진 버전과 기능 구현 후 실제 버튼 순서, 조건, 클래스·함수 링크를 추가합니다.
[공통 템플릿](../TEMPLATE.md)의 항목을 따라 상세 내용을 확장합니다.
