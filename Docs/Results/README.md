# 측정 결과 작성 규칙

현재 실측 결과 없음.

- 각 결과에 Run ID, 프로젝트 커밋, 엔진 버전, 장비, 빌드, 실행 인자와 설정을 기록합니다.
- 실제 연결 수와 서버 AI·부하 액터 수를 분리합니다.
- 생성 순간, 안정화, 유지, 상태 변경 구간을 분리합니다.
- A/B는 동일 배치·시드·동선·수집 조건으로 초기화 후 반복합니다.
- 초기 제안: 30초 준비 후 120초 수집, 3회 반복. 실제 조건은 실험별로 명시합니다.
- 서버 작업 시간과 Tick 제한에 따른 대기 시간을 구분합니다.
- 평균·p95·p99의 대상과 집계 방법을 명시하고 단위를 표기합니다.
- CPU·송신량 감소뿐 아니라 상태 지연·이동 보정·정확성도 확인합니다.
- 필터링과 우선순위 실험에서는 플레이어 밀집·분산을 구분합니다.
- 네트워크 지연 주입 값은 실제 RTT와 별도로 표시합니다.
- 한 PC에서 서버·클라이언트를 함께 실행하면 자원 경쟁을 한계에 기록합니다.
- 상세 트레이스 수집 비용을 고려하고 A/B의 수집 옵션을 일치시킵니다.
- 요약 Markdown·CSV·그래프·캡처는 추적하고 원본 `.utrace`는 `Artifacts/` 등에 로컬 보관합니다.
- 원본 공유 시 별도 다운로드 위치와 해당 Run ID를 연결합니다.
